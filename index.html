핵심 요구사항 분석

  • 생체 데이터 연동·수집: 클라이언트 제공 센서 환경(체온·혈압·심박수)으로부터 실시간 송출되는 데이터를 수신·인식
  • 건강 상태 판단 로직: 클라이언트 제공 판별 기준에 따라 정상/이상 상태 계산 및 출입 가능 여부 도출
  • 출입 통제·안내 UI: 측정 진행 → 결과 → 출입 허용/차단을 시각적으로 안내하는 키오스크 인터페이스
  • 하드웨어 제어 신호 송출: 판별 결과에 따라 게이트(출입문) 개폐 신호 연동
  • 범위 외: 관리자 페이지(Admin), 데이터 축적/통계는 본 프로젝트에서 제외

제안 포인트

  1. 헬스케어 도메인 수행 경험: 시니어 주간보호 관리 플랫폼(Harmony Link, 약 6개월) 등 건강 데이터를 다루는 서비스의 안정성·정확성 흐름 구현 경험 보유
  2. 디바이스 센서 데이터 검증 로직 구현 경험: 모바일 헬스케어 앱(DayStarter)에서 디바이스 내장 센서(ML Kit·조도·배터리) 기반 행동 검증 로직을 직접 구현한 경험 → 본 프로젝트의 외부 생체 센서 데이터 수신·판별 흐름 설계에 그대로 적용
  3. BLE 무선 하드웨어 통신 구현 경험: BLE 근거리 디바이스 통신 모듈을 적용한 크로스플랫폼 앱(Connectin) 수행 경험 → 시리얼·USB 통신은 Flutter 표준 라이브러리(usb_serial, flutter_libserialport)를 Platform Channel로 연결하여 동일한 패턴으로 구현
  4. Flutter 기반 Android 앱 다수 출시 → Kiosk Mode 적용: Calendar Share·DayStarter·Fortune App·Harmony Link·Connectin 등 Flutter Android 앱 다수 출시 경험을 바탕으로 Android Lock Task Mode·자동 부팅·백그라운드 진입 차단을 적용
  5. 측정 → 판별 → UI → 게이트 제어 단일 흐름 설계: 센서 수신부터 게이트 제어 신호까지 단일 디바이스에서 완결되는 상태 머신 구조로 안전하게 설계 (오류·통신 끊김 시 차단 기본값)
  6. 충분한 통합 검증 시간 확보: 60일 일정 중 마지막 10일을 실제 센서·게이트 환경 통합 테스트와 24시간 연속 가동 확인에 할당하여 안정적 인수인계

PRD (Product Requirements Document)

프로젝트 요구사항을 정의하고 기능 범위를 명확히 합니다.

1. 프로젝트 배경 및 목적

본 프로젝트는 헬스케어 환경에서 출입자의 건강 상태(체온·혈압·심박수)를 실시간으로 체크하고, 정상으로 판별된 경우에만 출입을 허용하는 무인 키오스크 SW를 구축하는 것을 목적으로 합니다. 키오스크 단일 디바이스에서 측정·판별·안내·게이트 제어가 모두 완결되어야 하며, 별도의 관리자 페이지나 데이터 축적 기능은 본 프로젝트 범위에서 제외됩니다.

당사가 수행하는 범위는 (1) 클라이언트 제공 센서 환경에서 송출되는 생체 데이터의 수신·인식, (2) 클라이언트 제공 판별 로직 적용, (3) 측정 진행 및 결과 안내 UI, (4) 출입 게이트 개폐 신호 송출까지의 키오스크 SW 전체입니다.

2. 사용자 정의

운영자 (현장)키오스크 디바이스를 현장에서 운영·관리하는 인원디바이스 상태 확인, 오류 발생 시 안내 화면 인지, 재시작 절차 수행

3. 기능 요구사항

3.1 생체 데이터 연동·수집

  • [필수] 클라이언트 제공 센서 환경(체온·혈압·심박수)으로부터 송출되는 데이터 실시간 수신
  • [필수] 통신 인터페이스(시리얼/USB/BLE/네트워크) 협의 후 모듈 구현 — Platform Channel 기반
  • [필수] 수신 데이터의 유효성 검증 및 타임아웃·재시도 처리
  • [필수] 측정 단계별 진행 상태 화면 동기화

3.2 건강 상태 판단 로직 처리

  • [필수] 클라이언트 제공 판별 기준(임계값·조합 조건 등) 적용
  • [필수] 정상/이상 여부 계산 및 출입 가능 여부 도출
  • [필수] 판별 결과 로그(키오스크 로컬, 단기 보관) — 운영자용 디버깅 용도, Admin/통계 제외

3.3 출입 통제 및 안내 UI/UX

  • [필수] 홈/대기 화면 — 측정 시작 안내
  • [필수] 측정 진행 화면 — 단계별 가이드, 진행 상황 표시
  • [필수] 측정 결과 화면 — 정상/이상 시각적 안내
  • [필수] 출입 허용/차단 안내 화면 — 게이트 동작 동기화
  • [필수] 오류·재측정 안내 화면 — 센서 미감지·통신 실패 등

3.4 하드웨어 제어 신호 송출

  • [필수] 판별 결과에 따른 게이트(출입문) 개폐 신호 송출
  • [필수] 송출 인터페이스(시리얼·HTTP·GPIO 등) 클라이언트 환경에 맞춰 협의 후 구현
  • [필수] 게이트 제어 결과(성공/실패) 확인 및 UI 동기화

3.5 키오스크 디바이스 운영

  • [필수] Android Kiosk Mode 단일 화면 잠금
  • [필수] 부팅 시 자동 실행, 백그라운드 진입 차단
  • [선택] 일정 시간 미사용 시 자동 홈 복귀

5. 기술 제약사항

  • 키오스크 운영 OS·디바이스 사양은 클라이언트 환경에 따라 협의 (기본 권장: Android 11+ 산업용 태블릿/올인원 키오스크)
  • 센서 통신 인터페이스(시리얼·USB·BLE·네트워크)는 클라이언트 측 송출 환경에 맞춰 구현
  • 건강 상태 판별 기준 및 임계값은 클라이언트가 제공하는 로직을 그대로 적용 (의학적 판단 책임은 당사 범위 외)
  • 출입 게이트 제어 인터페이스(릴레이/제어 보드/네트워크 명령 등)는 클라이언트 환경에 맞춰 연동

6. 범위 외 사항 (Out of Scope)

  • 관리자용 어드민 페이지(Admin) 개발
  • 측정 데이터 영구 축적 및 통계·리포트 화면
  • 센서 하드웨어 조달·구성 (클라이언트 제공)
  • 판별 로직 자체의 의학적 설계 (클라이언트 제공)
  • 출입 게이트 하드웨어(잠금장치·게이트 본체) 조달
  • 키오스크 디바이스 구매·설치 작업 (현장 인수인계만 수행)
  • 운영 기간 중 서버 호스팅 및 24/7 모니터링 운영 대행

Connectin — 디지털 명함·근거리 네트워킹

프로젝트 개요

BLE 근거리 탐색을 활용한 디지털 명함·네트워킹 앱. 모바일 디바이스 간의 하드웨어 통신과 보안 설계를 단일 코드베이스(Flutter)에서 구축.

핵심 기능

  • BLE 근거리 디바이스 탐색·페어링
  • OCR 명함 스캔, Signal Protocol E2E 암호화
  • 크로스플랫폼 (Android/iOS) 단일 코드베이스
  • 외부 슈퍼앱(Zalo) 연동

  • Platform Channel 활용: Flutter에서 네이티브 하드웨어 API에 접근하는 구조 경험
  • 크로스플랫폼 단일 코드: 추후 디바이스 OS 변경(Android → 윈도우 등) 시에도 화면·로직 코드 재활용 가능
